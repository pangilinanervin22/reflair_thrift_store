# ReFlair — a one-of-each thrift store

A portfolio e-commerce project: a curated archive of pre-loved fashion where every piece exists exactly once. Browse, save, bag and "order" (cash-on-delivery, demo only) on the storefront; manage pieces, orders and customers in the admin atelier.

> **Demo notice.** This is a learning project. Nothing on the live site is for sale, no payments are collected, and demo data may be reset at any time.

**Live:** https://reflair-thrift-store.vercel.app

## What it does

**Storefront**
- Home, three category rails (women / men / shoes) and an archive with search (name, material, colour), sorting and pagination — all static or ISR-friendly, regenerated on demand when the catalogue changes.
- Piece pages with sold state, related pieces, Open Graph card and `Product` / `BreadcrumbList` structured data.
- Accounts: sign up / sign in (credentials), profile with Bacoor barangay picker, bag, saved pieces, orders with cancellation while pending.
- Checkout that claims pieces atomically — two shoppers can never buy the same one-of-one item.

**Admin (staff only)**
- Dashboard: monthly sales, sold pieces by category, latest pieces, recent orders.
- Products (create / edit / delete with image upload), orders (status flow with a transition table, cancellation returns pieces to the archive), customers.

**Engineering**
- Server actions with session-derived identity (`requireUser` / `requireAdmin`) and zod-validated input; no client-supplied identity anywhere.
- Static storefront + on-demand revalidation; security headers; metadata, sitemap, robots, manifest and social images generated by the app.
- Accessible controls (real buttons, one `h1` per page, AA contrast), Philippine-time date formatting, peso formatting.

## Stack

Next.js 16 (App Router, React 19, TypeScript strict) · Prisma 6 on MongoDB Atlas · next-auth v4 (credentials + bcryptjs) · zod 4 · UploadThing v7 · SCSS modules · react-toastify · recharts · vitest · deployed on Vercel.

## Getting started

Prerequisites: Node 22+, npm, a MongoDB Atlas cluster (free tier is fine), an UploadThing app.

```bash
git clone https://github.com/pangilinanervin22/reflair_thrift_store.git
cd reflair_thrift_store
npm install                  # also runs `prisma generate`
cp .env.template .env        # then fill in the values below
npx prisma db push           # creates the collections in your database
npm run dev                  # http://localhost:3000
```

### Environment

| Variable | Notes |
|---|---|
| `DATABASE_URL` | Atlas SRV string. It **must** include the database name — `…mongodb.net/reflair?appName=…`. Without it every query fails with `empty database name not allowed`. |
| `NEXTAUTH_SECRET` | `openssl rand -base64 32` |
| `NEXTAUTH_URL` | `http://localhost:3000` locally; the production URL on Vercel |
| `UPLOADTHING_TOKEN` | From the UploadThing dashboard (v7 token) |

`.env.template` holds placeholders only — never commit real values.

### Creating an admin

There is deliberately no admin sign-up. Register a normal account on `/register`, then set its `role` to `"admin"` directly in MongoDB (Atlas UI, Compass or `mongosh`):

```js
db.Account.updateOne({ email: "you@example.com" }, { $set: { role: "admin" } })
```

Sign in at `/admin`.

## Project layout

```
src/app/(shop)      storefront routes (static home/rails/pieces, dynamic archive & account)
src/app/admin       admin atelier (gated in layout.tsx; every action re-checks the role)
src/app/api         auth, cart badge, UploadThing — nothing else
src/lib             server actions (*Action.ts), auth helpers, zod schemas, constants, JSON-LD
src/components      shared UI (nav, footer, error/404 states, admin table, dialog)
src/scss            design tokens and global styles
prisma/schema.prisma  Account · Product · Order · Cart · Like
```

## Deployment

Hosted on Vercel. Configure the four environment variables in the project settings and deploy with `npx vercel deploy --prod`. The build prerenders the storefront against the live database, so a wrong `DATABASE_URL` fails the build rather than the runtime.
